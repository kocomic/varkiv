# 隐私与本地数据边界

Varkiv 是自托管工具。当前版本没有遥测、分析、广告、崩溃上报或内置在线刮削器，也不会把资料库内容发送给 Varkiv 项目维护者或第三方服务。

可选的本地 EmulatorJS 目录是操作者明确提供的只读运行资源，不进入 SQLite、状态备份、整合包或项目镜像。正式 Compose overlay 只挂载该目录本身，并禁止 Docker 在宿主路径缺失时创建空目录；外部资源 URL 模式则会让用户浏览器直接访问所配置的固定来源，应由操作者自行评估该来源的网络隐私边界。

## 数据流

| 数据 | 保存位置 | 会发送到哪里 |
| --- | --- | --- |
| ROM、BIOS、媒体 | 用户明确配置的资料库，或显式选择的受管存储 | 不发送；仅在用户确认生成整合包时复制到该输出目录 |
| 图片缩略图 | 自托管状态根下不含原文件名的 0700/0600 内容寻址缓存 | 不发送；仅返回给已通过当前服务鉴权的 Web 客户端 |
| ROM 指纹 | 自托管服务数据库 | 配对 Agent 只向用户配置的自托管服务发送 SHA-256、大小和不含路径的可移植 ID |
| ROM 歧义确认 | 自托管服务数据库 | 保存设备、Agent 不透明条目标识、ROM 身份摘要、候选集合摘要和所选 Edition；管理界面/API 不返回路径、文件名、客户端条目标识或匹配标识原值 |
| 存档内容 | 设备上的显式存档根与自托管服务的内容寻址存储 | 仅在已启用 SaveBinding 时，在该设备与用户配置的自托管服务之间传输 |
| 管理令牌 | 当前浏览器标签页的 `sessionStorage` | 仅随请求发送给当前打开的 Varkiv 服务源站 |
| 设备令牌 | 设备私有配置；服务端只保存摘要 | 仅随同步请求发送给配置中的自托管服务；不会进入整合包清单或验收报告 |
| 设备路径、ROM 名、存档名 | 设备本机 | 不进入中央 inventory、同步状态或验收报告 |
| Android SAF 默认/模拟器专属目录 URI | Android Agent 私有 SharedPreferences 与系统持久授权 | 不发送；服务端只提供声明式模板，客户端在对应授权树内解析 |
| Android 模拟器/core 单文件授权 URI | Android Agent 私有 SharedPreferences 与系统持久只读授权 | 只哈希服务端为该设备 OS/架构明确要求的文件；仅向用户自己的服务发送公开对象 ID、合同版本、SHA-256 和大小，不发送 URI、路径或文件名 |
| 运行和错误信息 | 本机日志或本机状态 | 使用固定状态码；不得包含 token、存档内容或宿主绝对路径 |
| 完整状态备份 | 用户明确指定的新本地目录 | 不上传；包含完整数据库、受管原件和相对文件名，应视为与原资料同等私密；不包含可重建缩略图 cache 或未提交上传暂存 |
| 受管清理恢复清单 | `state/recovery/managed-storage`，权限 0600 | 不上传；历史 API 只返回数量、容量、状态和时间，原相对路径只留在私密清单 |

当前代码中的外部网址只用于文档、公开兼容性证据或输入示例；服务不会在后台访问这些地址。未来若增加在线元数据提供器，必须默认关闭，并在启用前列出提供器、发送字段、目的和保存策略。

仓库本身还执行源码卫生门禁：CI 与发布流水线同时检查已跟踪文件和未被忽略的新文件，拒绝未知 ROM/整合包、媒体、存档、数据库、签名材料、机器专属 macOS 路径、私钥/常见提供商令牌特征和超过 8 MiB 的单文件。九个带 ROM 扩展名的测试输入均为 24–86 字节的合成文本夹具，两张 559/583 字节 SVG 为合成封面；全部锁定路径、大小与 SHA-256，仅把扩展名改成“测试文件”不能绕过门禁。

## 扫描与文件操作

- 服务只扫描启动参数或 API 中明确配置、且位于资料库根内的来源；Go Device Agent 只扫描逐项授权的 ROM、存档、模拟器和 core 根；Android Agent 只读取用户逐项授权的 ROM/存档树和服务端当前要求的模拟器/core 文件。
- 扫描器不跟随越过授权根的符号链接，不搜索用户主目录、整块磁盘、注册表或 NAS 的其他共享目录。
- 引用模式不移动、重命名、修改或删除源文件。复制模式写入新的受管 Edition 目录；目标已存在时拒绝合并或覆盖。
- 缩略图每次命中或返回 304 前仍先验证原件的普通文件类型、大小和 SHA-256。损坏或符号链接缓存只替换精确的服务缓存入口，不读取或改写其目标；原件缺失或漂移时不会返回旧图。Web 原件回退只允许 WebP、AVIF、BMP 和 icon；引用来源中的 SVG/HTML 等主动内容不会被界面请求或渲染。
- 导出只更新当前 package manifest 管理的文件。额外文件保留；更新前建立独立、永久的可恢复快照。
- CLI `build-pack` 只从显式 `--library` 读取引用型资源，并只从显式 `--state`（省略时为数据库目录）的 `roms/` 与 `media/` 读取受管资源；不会在两类根之间猜测、搜索主目录或扫描其他 NAS 路径。
- 存档下载先复制并校验旧内容，再在目标同卷构造和校验新内容，最后原子替换。恢复备份不自动清理。
- 失败清理仅能删除当前操作创建并持有的随机暂存对象，或回滚 manifest 精确声明为本次新建的文件。
- 受管存储维护不会扫描外部资料库、NAS、存档、媒体上传暂存区或可重建缩略图 cache。它只把数据库未引用且位于 `state/roms`/`state/media` 原件区的普通文件列入签名预览；人工选中并确认后只移动到同卷恢复区。符号链接或特殊文件会中止原件扫描，恢复时任何目标碰撞都会让整批停止且不覆盖。
- `runtime-hints list` 只读打开现有数据库，文本与 JSON 都不会输出来源文件路径或原始前端命令。CLI 只能把用户按 ID 明确选择的可信结构化侧车建议转为 LaunchBinding；可能含本机路径或 shell 语义的 Pegasus/ES-DE 原始命令保持不可执行，必须在 Web 中另行审查。
- `backup-state` 不读取外部资料库，只读取显式数据库和 state 根；`restore-state` 只创建一个尚不存在的新根。两者不会把路径、文件名或内容写入控制台，只输出 schema、文件、字节与资源计数；备份目录本身可能包含游戏名和存档内容，不应提交仓库或公开分享。
- `agent target-package verify` 只读用户明确指定的私有目标包，不跟随符号链接，也不修改权限、修复文件或删除额外项。文本/JSON 结果仅返回公共 target、文件数和缺失/变化/权限/不安全/额外项计数，不输出 token、文件内容或宿主绝对路径。
- `acceptance-container.sh` 只挂载仓库虚构 `testdata`，不会接受或自动发现生产资料库/state 路径。它为容器和三个卷生成唯一名称，在容器启动前登记所有权，并在成功、断言失败、端口冲突或中断时只清理这些精确资源；随机验收令牌不输出。

## 访问控制

- 服务默认只监听回环地址；非回环监听必须设置管理令牌。
- 设备使用可单独撤销、带过期时间和最小 scope 的 token；不能访问管理 API、其他设备或管理员恢复 ZIP。
- Go 与 Android Agent 的配对、认证 JSON、存档上传和逐文件下载共用同一网络边界：固定超时，禁止 HTTP 重定向，Bearer token 和存档字节不会被转发到第二源站；会进入 URL 路径的服务端 ID 必须是最长 128 字符的不透明安全段，内容哈希必须是规范 SHA-256。JSON 响应最多读取 8 MiB；单个 revision 最多 4,096 个文件、合计 240 MiB，服务端仓库和两个客户端分别执行上限与实际内容哈希校验。
- 存档 revision 的逻辑路径使用与宿主系统无关的可移植合同：拒绝绝对路径、盘符、点段、控制字符、Windows 保留名和不可跨端创建的名称。单文件绑定只上传 `primary.<安全扩展名>`；设备本地 ROM/save basename、绝对路径和 Android SAF URI 不进入中央状态或错误文本。
- 数据库持久化和管理员 ZIP 恢复入口会再次校验相同的 Unicode/路径、唯一性与 4,096 文件/240 MiB 聚合合同，不能用旧记录或绕过同步仓库制造不可在另一端安全恢复的路径。网页核心没有生成持久存档文件时不会创建占位 revision。
- ROM 歧义确认属于管理员控制面。设备 token 无法枚举候选、生成签名预览或提交确认；签名预览在 ROM 身份、候选集合或选择变化后失效。
- Unix 上设备配置强制为 `0600`；Windows 上使用只允许当前用户与 LocalSystem 的 protected DACL。无法安全收紧权限时 Agent 拒绝读取配置。
- 明文 HTTP 只允许回环；局域网明文连接还需要显式危险确认。建议通过 HTTPS 反向代理或可信 VPN 使用。

## 本地验收报告

`varkiv agent acceptance` 只写入一个用户指定的新本地文件，拒绝覆盖，也不会自动上传。报告不包含服务地址、令牌、设备/profile/stream ID、设备名、本地路径、ROM/存档名或底层错误；它始终标为候选证据并要求人工复核。

## 删除与卸载

Varkiv 当前不提供自动永久删除 ROM、媒体原件、存档、恢复快照或额外导出文件的功能。设置页的“移入恢复区”是可逆隔离，不是删除，也不会立即释放容量。卸载服务或 Agent 不应删除这些数据。需要释放空间时，由用户在核对恢复清单和备份后使用精确目标处理；项目不会给出宽泛递归删除命令。

## 漏洞与隐私问题

隐私泄露按安全漏洞处理。请按仓库根目录的 [SECURITY.md](../SECURITY.md) 私密报告，不要附带真实 ROM、BIOS、密钥或个人存档。私密报告渠道启用前，本项目不宣称适合直接暴露到互联网。
