# 贡献许可政策

状态：**Apache-2.0 inbound = outbound**

本页是项目治理说明，不替代仓库根目录的 [Apache License 2.0](../LICENSE)，也不构成法律意见。

## 当前政策

Varkiv 自身以 Apache-2.0 发布。按照该许可证第 5 节，贡献者有意提交并获项目接收的代码、文档、配置和素材，默认同样按 Apache-2.0 提供，不附加额外条款；明确标记为 “Not a Contribution” 的交流内容不视为贡献。

当前预览阶段不要求额外签署 CLA，也不要求 DCO `Signed-off-by`。这避免为了小型个人维护项目额外收集签署记录或身份资料。若未来因双重许可、法律主体或大规模企业贡献而需要改变机制，新政策只对其生效后的提交适用，并在接受新贡献前公开说明。

## 提交者需要确认

提交 pull request 即表示提交者确认：

- 有权按仓库声明的许可证提交相关内容；
- 第三方代码、图标、字体、数据或其他素材已标明来源和许可证，且允许再分发；
- 不包含商业 ROM、BIOS、固件、密钥、个人存档、访问令牌或未经授权的媒体；
- 雇佣、委托或组织政策不会阻止该提交；
- 知道提交、作者信息和讨论将公开保存，并可能随项目再分发。

使用生成式工具不改变上述责任。提交者应披露影响审查的重要生成过程，并亲自核对行为、来源、许可证、安全与测试结果；工具不能替提交者作权利声明。

## 项目维护边界

- 合并不等于接受与 Apache-2.0 不兼容的额外条款。
- 项目不会因为便利而复制其他组织的 CLA、商标授权或隐私条款。
- 项目名称和标志的商标使用不由 Apache-2.0 自动授权。
- 依赖与可选运行时继续适用各自许可证，详见 [第三方声明](THIRD_PARTY_NOTICES.md)。

Apache-2.0 的唯一完整法律文本是仓库根目录的 `LICENSE`；翻译、README 摘要和本页都不是许可证正文。
