# UI 语言与视觉规范

本文件约束 Web 控制面的文字、图标和布局，避免页面在继续扩展后重新出现风格漂移。

## 信息层级

- 页面标题只说明当前任务；简介保持一句话。
- 主流程只展示完成当前步骤所需的字段、状态和不可忽略的安全警告。
- 原理、边界和证据放入默认收起的 `details`；不能把删除、覆盖、缺失 ROM 或隐私风险藏进折叠区。
- 不重复解释按钮已经表达的动作。成功反馈给出结果和数量，失败反馈给出可修复原因。
- 游戏库默认使用管理列表；卡片只用于封面浏览、设备选择等确实需要视觉比较的场景。

## 用词

- 对用户使用“游戏、版本、ROM、媒体、来源、整合包、设备、存档”，不暴露内部 `Work`、数据库表名或实现缩写。
- 界面语言使用完整名称：简体中文、繁體中文、日本語、English。不要显示“简中、繁中”等自造简称。
- 技术名词只在它是用户需要识别的真实格式时保留，例如 Pegasus、ES-DE、SHA-256、RetroArch。
- 所有新增可见字符串必须同时提供 `zh-CN`、`zh-TW`、`ja`、`en`，并在每种语言下检查溢出。
- 动态生成的表格、卡片、弹窗、`aria-label`、`placeholder` 和状态切换文案也属于界面语言；不能只翻译初始 HTML。

## 图标

- 使用 `index.html` 中的 24×24 SVG sprite；描边采用直角端点与斜接转角。
- 状态、来源和操作图标不得混用 emoji、Unicode 符号或 `P`、`ES`、`LM`、`CFG` 等字母徽标。
- 新增、关闭、更多、折叠、前进、上传和下载统一引用 sprite；不要在 DOM 中留下 `＋`、`×`、`•••`、`⌄`、`→` 或 `↑↓` 充当图标。
- 同一语义复用同一图标：新增、确认、警告、前进、ROM、元数据、配置和引用各只有一个图形。
- 图标只辅助文字。只有关闭、更多等通用图标按钮可以不显示文字，但必须保留准确的 `aria-label`。
- 平台缩写属于平台识别信息，可以出现在平台标记中；它不是操作图标。

## 布局

- 页面采用任务区而不是无差别卡片墙；列表行、选择行和表格优先。
- 同组选择项必须等宽、同内边距、同图标盒尺寸，内容较长时截断辅助行而不是撑大容器。
- 桌面和 390px 掌机宽度都不得出现页面级横向滚动；隐藏的原生单选框不得参与布局宽度。
- 正文和控件遵循 `styles.css` 的类型变量，不以 10px/11px 作为主要阅读字号。

## 验收

```bash
node --check internal/server/web/app.js
node --check internal/server/web/i18n.js
npm run test:e2e
```

Playwright 会检查四种语言、英文界面中文污染、顶栏状态切换、五类编辑器、资料库动态内容、渐进披露、常用视口溢出、图标 sprite 引用和关键流程。视觉改动还应在真实浏览器中检查游戏库、平台、来源、整合包和设置页。
